Redesign Agent: give it a legacy website URL, get back a better site and its repo

A short chain of focused agents researches what an organization does, writes the story its site should tell, designs three directions, picks one with a judging council, builds it, tries to break it, and hands over the code. The target is one finished, tested product in seven days, built by three people in three separate lanes, each working with Claude and the master agents.

What it does

Old sites are hard to use, dated, or partly broken: a high school site with four pages where three do not load. The owner types the site's address. The product returns a redesigned site, built around what the organization does, with a repository the owner can keep.

Prompt-based builders such as v0 start from a blank page and a wish. This starts from the real site, so the content, images and purpose are already known. The difference is the research and the storyline: the new site is planned like a short film about the organization, then built.

ScoutCrawls every page. Records text, images, links, forms, and the old site's colors and type. Tags each text block with the page it came from.
StorytellerWorks out what the organization does and for whom. Writes a page-by-page storyboard.
Art directorWrites three design directions with type, color, layout and real reference sites.
CouncilThree vision models from different families compare the directions in pairs. A person breaks ties.
BuilderBuilds the chosen direction as a static site and runs accessibility and speed checks.
Red teamTries to break it: changed facts, missing pages, broken links, accessibility failures.
HandoffPreview link, the repository, and a report of anything it could not carry over.

What "done" means on Saturday

  • One command takes a URL and produces a site, a preview link, a repository and a fidelity report.
  • Run on three sites. In a blind comparison, at least 4 of 5 reviewers prefer the redesign to the original, and at least 3 of 5 prefer it to a one-shot redesign by plain Claude of the same site. Beating that baseline answers "Claude can already do this".
  • Every page, contact detail and link on the old site is carried over or listed as dropped, with a reason.
  • Zero serious accessibility violations from axe-core, and a Lighthouse accessibility score of at least 95 on mobile. These thresholds are proposed and can change.
  • The council ranks 25 award-winning sites above 25 legacy school sites in at least 90 percent of pairs. If it does not, it is not trusted as a judge.
  • A short demo video and a written summary that name what still needs manual work.

Who does what

Three lanes, zero shared files. Each person owns one folder, one branch prefix, one set of API keys and one dependency list. Nobody reads, runs, reviews or edits another lane's code. Work moves between lanes only as JSON files that match a contract frozen on Sunday night.

Rules that keep the lanes apart

  • Every lane has the same command shape: node lanes/<lane>/cli.mjs <stage> --run R --in … --out …. Exit codes: 0 ok, 2 bad input, 3 gate failed, 4 budget hit.
  • Contracts are frozen at tag contracts-v1.0.0 on Sun Nov 1, 21:00 PST. A change needs a GitHub issue labelled contract-cr. Abhinav rules within 12 hours. No breaking changes after Wed 09:00.
  • Each lane builds against sample data until Wednesday, then against real run outputs Abhinav publishes to contracts/samples/. Nobody waits on anybody.
  • CI fails any pull request from a lane branch that touches a file outside that lane's folder. CODEOWNERS makes each person the only reviewer of their own folder.
  • Daily sync: one line in your own STATUS.md by 21:00 PST. Abhinav's Claude rolls them up onto the shared board. Questions go on the board or a GitHub issue, never as edits.
  • If the orchestrator finds a lane failing, Abhinav posts the failing command and input file, and that lane's owner fixes it.

The stack

Use

  • Playwright and the sitemap for crawling
  • dembrandt (pinned version) for the old site's colors and type
  • Astro static output, Tailwind, Radix primitives
  • Motion or CSS scroll animation
  • axe-core and Lighthouse as blocking checks
  • OpenRouter for all models
  • screenshot-to-code and open-lovable as references and baselines

Avoid, and why

  • GSAP: its free license bars use in tools competing with Webflow
  • crawl4ai: adds a credit clause for commercial web apps
  • Magic UI: its stock components look like generic AI output
  • Lenis and WebGL on school sites: heavy on cheap hosting
  • TRIBE v2: non-commercial license, and it takes video, audio or text
  • New skill installs: none this week. Copy rule text at a fixed commit instead.

The review of these picks is in the devil's advocate report. The skills that came up (impeccable, taste-skill, Vercel's web-design-guidelines) run unpinned scripts or fetch their rules from a live branch, so their rules are copied into our reviewer prompt instead.
